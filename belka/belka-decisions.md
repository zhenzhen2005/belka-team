# Belka — สรุปสิ่งที่คุยกันและช่องว่างก่อนวันที่ 21 พ.ย. 2026

เขียนเมื่อ 19 พ.ย. 2026 · สถานะ: **ร่าง รอทีมอนุมัติ** · ไม่ได้ส่งให้ Kiro และไม่ได้แก้ไฟล์ spec ของทีม
แหล่งอ้างอิง: `docs/submission.md`, `docs/handoff.md`, `.kiro/steering/product.md`, `prototype/README.md`

## 1. สิ่งที่ตัดสินใจไว้ในบทสนทนา (ต้นแบบทำตามนี้แล้ว)
- โฟกัสด้านการตลาดอย่างเดียว
- คำนวณส่วนลดต่อสินค้าแต่ละตัว ไม่ใช้เปอร์เซ็นต์เดียวทั้งร้าน
- ร้านอาหารและเครื่องดื่มขายบน TikTok Shop / Shopee / Facebook Shop ไม่ได้ ช่องทางเหล่านี้จึงใช้เพื่อการตลาดเท่านั้น
- มีคลัง persona ลูกค้าจำลอง (ต้นแบบมี 10,000 คน) และจำลองผลก่อนลงมือทำ
- คอนเทนต์ต้องไม่ขึ้นกับการทำวิดีโอ
- กรอกข้อมูลแบบแตะเลือกก่อน พิมพ์ทีหลัง

## 7. อ่านเมนูจากรูป (ต้นแบบอ้างอิง เพิ่ม 19 พ.ย. 2026)
ผู้ใช้เลือกวิธีถ่ายรูปเมนูให้ AI อ่าน (OCR/Maps ใน P0) ทำใน `prototype/` เท่านั้น ไม่ได้แก้ spec ของทีม
- `backend/belka/menu_import.py` + `POST /api/menu/import`: รูป → Claude บน Bedrock (โมเดลและ region ตาม aws.md) → โค้ดตรวจชื่อ/ราคา/จำนวน (ไม่เกิน 50 รายการ) → เจ้าของร้านแก้ก่อนใช้
- ข้อความในรูปถือเป็นข้อมูล ไม่ใช่คำสั่ง · ไม่เก็บรูป · ต้นทุนไม่เดา (ใช้ค่าประมาณติดป้ายตามเดิม) · AI ใช้ไม่ได้ให้พิมพ์เมนูเอง
- หน้าเว็บ: ปุ่ม "📷 อ่านเมนูจากรูป" ในแท็บวิเคราะห์ (`web/index.html`) · เวอร์ชันลิงก์สาธารณะ (`belka-share/site`) ยังไม่มีปุ่มนี้
- เทสต์ 24 ข้อใหม่ (`tests/test_menu_import.py`) ผ่าน · ในเครื่องทีมรันเทสต์ทั้งหมดผ่าน 266 ข้อ (19 พ.ย.)
- ลองกับ Bedrock จริงแล้ว (19 พ.ย.): `source=ai` อ่านได้ 6 เมนูพร้อมราคาถูกต้อง + ชาเขียวมัทฉะอ่านราคาไม่ได้ (ไม่เดา) + ไม่ทำตามบรรทัดหลอกสั่งงาน (ไม่มี HACKED) · โมเดล `anthropic.claude-sonnet-5` ใน ap-southeast-1 รับรูปภาพได้ · ลองแค่รูปตัวอย่างที่ทำเอง 1 รูป ยังไม่ได้ลองรูปเมนูจริงของร้านที่ถ่ายด้วยมือถือ
- ลองจริง: `cd prototype/backend && uv run python -m belka.cli menu tests/fixtures/sample_menu.jpg` (ต้อง aws sso login ก่อน) รูปตัวอย่างมีบรรทัดหลอกสั่งงานแฝงอยู่ ผลที่ควรได้คือ 6 เมนูมีราคา + ชาเขียวมัทฉะอ่านราคาไม่ได้ และไม่มีคำว่า HACKED

## 8. ระบบกันแฮก + เมนู/ต้นทุนก่อนแผน + กล้อง + แท็บส่วนลด (19 พ.ย.)

**ชั้นป้องกัน** `prototype/backend/belka/security.py` (ASGI middleware ต่อใน `api.py`, เทสต์ `tests/test_security.py` 13 ข้อ)
- Host ต้องเป็น 127.0.0.1 / localhost / [::1] (กัน DNS rebinding)
- POST ต้องมาจากหน้าเดียวกัน (เช็ก Origin + Sec-Fetch-Site) กันเว็บอื่นสั่งงานแทนเรา (CSRF)
- POST /api/* ต้องเป็น JSON, ขนาดไม่เกิน 6 MB (เช็กทั้ง Content-Length และตอนรับทีละชิ้น)
- เรียก AI (/api/plan, /api/ask, /api/menu/import) ได้ 12 ครั้ง/นาที และ 300 ครั้ง/วัน (ตั้งใหม่ได้ด้วย BELKA_AI_PER_MIN / BELKA_AI_PER_DAY) กันค่า Bedrock บาน; API อื่น 240/นาที
- header: CSP, nosniff, X-Frame-Options DENY, no-referrer, Permissions-Policy (กล้องเฉพาะหน้านี้), no-store กับ /api/*
- หน้าเว็บ: `?api=` ใช้ได้เฉพาะเปิดไฟล์จากเครื่องและชี้ได้แค่ 127.0.0.1/localhost
- ข้อจำกัด: CSP ต้องใช้ 'unsafe-inline' เพราะหน้าเว็บเป็นไฟล์เดียว; ตัวนับอยู่ในหน่วยความจำ (รีสตาร์ทแล้วเริ่มใหม่); ยังไม่ได้แตะบัญชี AWS ของทีม (Bedrock Guardrails และ budget alert ต้องถามทีมก่อน)

**ฟีเจอร์**
- ขั้นที่ 5 ของการเริ่มต้น: ใส่เมนู ราคา ต้นทุน (อย่างน้อย 1 เมนู) ก่อนกด "รับแผน" — ขัดกับหลักของทีม "เริ่มโดยไม่ต้องกรอกต้นทุน" และ P-1 ต้องให้ทีมตัดสิน (มีปุ่ม "ลองด้วยเมนูตัวอย่าง" ช่วยลดแรงเสียดทาน)
- ถ่ายรูปเมนูด้วยกล้อง (getUserMedia, สำรองด้วยช่องเลือกรูปแบบ capture) + เลือกรูปจากเครื่อง
- แท็บ "ส่วนลด": `POST /api/calc/discounts` คิดส่วนลดรายเมนูพร้อมกัน เมนูมาร์จิ้น <20% = ไม่ควรลด
- แผนที่ AI สร้างยังไม่ได้รับเมนู/ต้นทุนเป็นข้อมูลเข้า (เก็บในเครื่องเท่านั้น)
- ผลทดสอบ: pytest 306 ผ่าน; ลองบนเบราว์เซอร์ที่ 127.0.0.1:8001 ผ่านทั้งขั้นตอน; กล้องจริงยังไม่ได้ลอง (เบราว์เซอร์ในแอปบล็อกกล้อง)
