Step 1 · about 15 minutes

Install Kiro, sign in and upgrade to Pro

1

Download Kiro

Go to kiro.dev and download the installer for your laptop. Get version 1.4.154 or later: P5a uses a new feature that older versions do not have.

2

Install and open it

Run the installer and follow it, then open Kiro (Windows: from the Start menu; macOS: drag it to Applications first). If your laptop is managed by your school or employer and blocks installs, tell the organisers now.

Sign in

Kiro asks you to sign in on first launch. Use Google, GitHub or a personal AWS Builder ID: these are the sign-ins that can buy a Pro plan. A Builder ID that is linked to an AWS account cannot be upgraded, so pick Google or GitHub if unsure.

Check: the profile icon in Kiro shows you signed in on the Free plan.

Your first Pro upgrade gives you the rest of this month free plus 500 trial credits, so the first US$20 charge arrives on the 1st of next month.

Step 2 · about 20 minutes

Install the agent tools and sign in to AWS

These are what P6 and P7 use in the session, and what 21 Nov deploys with. Run the commands in Kiro's terminal (View → Terminal).

Do the first three now. Installing uv, the AWS CLI and the AgentCore CLI needs no AWS account. The last item, signing in to AWS, waits for the organisers' message: leave it unticked until then.
1

Install uv and Python 3.12

uv installs Python and your agent's packages.

PowerShell (Windows)
winget install --id=astral-sh.uv -e
uv python install 3.12
Terminal (macOS)
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.12

winget comes with current Windows 10 and 11. If your laptop has no winget, follow the uv install page.

Check: uv --version prints a version. If the command is not found, close the terminal and open a new one.

2

Install the AWS CLI version 2

Run the official installer from PowerShell. It opens the Windows installer; accept the defaults.

PowerShell (Windows)
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi

Download and run the official package. It asks for your laptop password.

Terminal (macOS)
curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg"
sudo installer -pkg AWSCLIV2.pkg -target /

Check: open a new terminal, then aws --version starts with aws-cli/2. Other ways to install are in the AWS CLI install guide.

3

Install Node.js and the AgentCore CLI

Install Node.js 20 or later. Then install the AgentCore CLI at the version the AWS samples use. You need it on 21 Nov; installing it now means no installer on the day.

PowerShell (Windows)
winget install -e --id OpenJS.NodeJS.LTS
# or download it from https://nodejs.org/
# open a new terminal, then:
npm install -g @aws/agentcore@0.30.0
agentcore --version
Terminal (macOS)
# install the LTS version from https://nodejs.org/
# (or: brew install node)
# open a new terminal, then:
npm install -g @aws/agentcore@0.30.0
agentcore --version

If PowerShell says running scripts is disabled, run the npm line in Command Prompt (cmd) instead.

Check: it prints 0.30.0. Ignore the "Update available" message: stay on 0.30.0.

Team AWS sign-in

One team login, one phone to approve it

Your team has one AWS sandbox account and one shared login. The first sign-in sets up a second check on a phone. The team lead does that once. Then every builder connects their own laptop. Teams never get access keys: sign-in by the link is the only way in.

Why the first sign-in is a team job. The phone check is tied to the login, not to a person. Whichever phone is set up first is the phone Microsoft asks. If only the team lead has a phone registered and is asleep, nobody else can get in. So do the first sign-in together, on a call, and add more phones straight away.

Team lead: first sign-in (once, about ten minutes)

Browser on your laptop, phone in your hand

  1. Get the team on a call. Everyone who will build joins, each with a phone within reach.
  2. Open truecorp.awsapps.com/start. It sends you to a True sign-in page from Microsoft. A private (incognito) window helps: if Microsoft offers an account you already use, for example your employer's, choose Use another account.
  3. Sign in with the team login (an email address) and the password from the organisers. Microsoft should say Let's keep your account secure. If it asks you to approve a sign-in instead, a phone is already set up: stop and ask the organisers whose phone it is.
  4. Choose Next, then install Microsoft Authenticator. Install the free app from Google Play or the App Store, then choose Next on the laptop. No smartphone? Choose Other options, then Phone: Microsoft sends a code by call or text.
  5. Pair your phone. Microsoft shows a code to scan with the app, then sends a test sign-in to approve. If a two-digit number appears on the laptop, type it into the app.
  6. Reach the AWS access portal. The page changes to the AWS access portal and lists your team's account. If the list is empty, tell the organisers your team number.
  7. Add a second way in. While signed in, open mysignins.microsoft.com/security-info, choose Add sign-in method and add a second phone, for example your deputy's. If it will not let you, ask the organisers to reset the check.
  8. Share the login in your private team chat only. Never in a public channel, never in a file in your project, never in Kiro.

Teammates: get in, then add your own phone

  1. Open the start link and sign in with the team login. Microsoft sends the approval to the phone that was set up first, the lead's. If a two-digit number appears on your laptop, read it to the lead, who types it into the app and approves.
  2. While signed in, open mysignins.microsoft.com/security-info, choose Add sign-in method, pick Microsoft Authenticator and pair your own phone.
  3. Next time, approve on your own phone. If Microsoft asks the lead's phone, choose Sign in another way.

Every builder: connect your laptop

Step 2, last item, has the commands: aws configure sso with start URL https://truecorp.awsapps.com/start, SSO region and default Region ap-southeast-1, profile default; then aws sts get-caller-identity to confirm your team's account. When it expires, run aws sso login (or aws sso login --use-device-code if the browser does not open).

Regions you may use

RegionCodeUse it for
Asia Pacific (Singapore)ap-southeast-1Your default. Everything in this guide uses it.
Asia Pacific (Thailand)ap-southeast-7Allowed. Check that a service is offered there before you plan around it.
US East (N. Virginia)us-east-1Allowed. The AWS MCP Server that Kiro uses is hosted here.
Amazon Bedrock: use anthropic.claude-sonnet-5 in ap-southeast-1. Model IDs that start with global. or apac. send the request on to other Regions, so your account refuses them.

Any other Region is refused with an error that mentions a service control policy: switch the Region and run it again. Account-wide services (IAM, sign-in, CloudFront, Route 53, Budgets, Cost Explorer) are not blocked. Set the Region every time: top right in the console, --region in the terminal, and by name in code. You cannot create IAM users, access keys or console passwords.

Budget

WhatValue
Suggested spendUS$30 a day. Treat it as your daily ceiling.
Hard limitUS$500 per team account for the whole programme, which runs to the final on 12 Dec.

US$30 is a ceiling for a heavy day, not an allowance. If your team goes on to the final on 12 Dec, US$500 spread over the four weeks is about US$17 a day. Spend more on build days and almost nothing on the days between.
Still being confirmed. What happens when the limit is reached, and where the 80% alert goes. Until the organisers confirm, do not count on anything stopping by itself: assume what you leave running keeps costing money.
  1. Every morning, look at yesterday: Billing and Cost Management, then Cost Explorer, if your role allows it. Figures arrive about a day late.
  2. Every session, delete what you finished with. Some services bill by the hour even when idle, for example the vector store behind a knowledge base.
  3. Keep test runs small: short prompts, a few questions at a time, and a step limit on the agent. Most of the cost is input, and it grows with every turn.
  4. In agents, set a maximum number of steps and keep prompts and test files short.
  5. Use seed data only: small made-up files.
  6. Name one builder who checks the spend each day and tells the team when the total passes US$250, half the limit.
