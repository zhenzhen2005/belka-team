ถ้าต้องแก้ไฟล์ของอีกคน ให้ส่งข้อความบอกก่อน แล้วรอให้เขา Push งานของเขาก่อน

## 2. วงจรทำงาน (ทำซ้ำทุกครั้ง)

1. **Pull ก่อนเริ่ม** ใน GitHub Desktop กด Fetch origin แล้ว Pull origin (หรือกด Sync ที่ Source Control ใน Kiro)
2. ทำงานชิ้นเล็ก ๆ ให้เสร็จ
3. **รันเทสต์** ถ้าแก้ฝั่งหลังบ้าน: เปิดเทอร์มินัลใน `prototype/backend` แล้วรัน `uv run --with fastapi --with httpx --with uvicorn pytest -q` ต้องผ่านทั้งหมด
4. **Commit** ตั้งชื่อสั้น บอกว่าทำอะไร เช่น "เพิ่มป้ายคุ้ม/เสี่ยง/ไม่คุ้ม"
5. **Push origin ทันที** อย่าเก็บงานค้างข้ามชั่วโมง

## 3. ถ้าไฟล์ชนกัน (conflict)

- GitHub Desktop จะแจ้งว่าไฟล์ไหนชน ให้เปิดดู แล้ว**ถามอีกฝ่ายว่าจะเก็บของใคร** อย่าเลือกเองเงียบ ๆ
- ไม่แน่ใจ ให้ยกเลิก (Abort merge) แล้วสำเนาไฟล์ของตัวเองเก็บไว้ก่อน

## 4. ห้ามเด็ดขาด

- **ห้าม Commit รหัสผ่าน คีย์ AWS หรือไฟล์ `.env`** (ถ้าเผลอ ให้บอกทีมทันที และเปลี่ยนคีย์)
- ห้ามกด Force push
- ห้ามลบไฟล์ของอีกคนโดยไม่ถาม
